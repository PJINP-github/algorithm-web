# 本轮：YAML 通用模型标签页兼容方案问题

更新时间：2026-09-18

## 已确认的技术事实

- 当前右下角模型标签页、模型动作、动作执行和上传目录仍由 Rust/JavaScript 固定实现。
- `model/authority.yaml` 当前只能控制已有模型的标签页可见性、权限、文件白名单和日志行数，不能仅通过新增 YAML 自动创建未知模型。
- `Image_filtering_processing-tag0.0.1+python` 当前是命令行脚本，入口为 `similar_group.py --input <文件夹> --config <配置>`，会递归扫描图片，并可能删除模糊图片或组内超额图片。
- 当前网页上传接口一次处理一个文件；当前“本机导入”也只允许复制单个文件，尚不支持文件夹导入。

## 建议采用的兼容边界

建议第一阶段建立“通用模型标签页协议”：

1. 现有五个固定标签页保持原行为，不强制迁移。
2. `authority.yaml` 新增通用 `Tab_content` 区域，声明新增标签页、按钮、参数组件、日志和输出文件。
3. 新模型目录提供固定入口，例如 `portal_entry.py`，Rust 只按统一协议启动它，不再为每个新模型增加 `match` 分支。
4. 第一阶段只支持有限的通用组件：导入文件、导入文件夹、模式切换、单选/多选参数、文本/数字参数、运行按钮、日志、最新文件和输出文件夹。
5. 需要完全自定义的复杂界面暂不纳入第一阶段；否则仍需为该模型增加独立前端代码和路由。

# 本轮：离线包审核任务局域网访问、独立端口和并发隔离问题

## 已确认的当前实现事实

- Rust 主服务已经绑定 `0.0.0.0`，但离线包 M/H 审核任务当前由 `execute_offline` 强制传入 `--host 127.0.0.1` 和 `--interaction-mode local`。
- Python 离线审核服务支持传入监听地址和首选端口；端口被占用时会从首选端口继续寻找空闲端口。
- Python 的局域网模式可以输出局域网 IP，但当前 Rust 前端只识别日志中的 `http://127.0.0.1:<port>`，不能识别局域网地址。
- Rust 为每个任务创建独立的输入、输出和临时目录；当前任务并发池最多同时运行 4 个任务。
- H 模式默认使用模型目录根部的 `annotations.sqlite3`。多个 H 任务并发写入同一个 SQLite 文件，是否需要额外串行化或按任务隔离，当前尚未确认。
- Windows 是否允许动态端口通过防火墙从局域网访问，取决于发布机的防火墙策略；代码只绑定监听地址不能自动保证防火墙放行。
