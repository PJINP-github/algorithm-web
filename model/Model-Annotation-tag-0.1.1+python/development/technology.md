# 技术方案与脚本说明

## 整体架构

```
1.task_id.py → 数字-1-标注任务明细.txt + 数字-8-原始标注类别清单.txt
      ↓
2.model.py   → 数字-9-标准训练类别清单.txt + 数字-4-模型训练记录.txt  (解析 数字-7-类别标准化映射规则.txt，爬取 model 数据)
      ↓
3.sum_up.py  → 数字-5-训练展望原始分组.txt               (匹配 ask + model，标注训练状态)
      ↓
4.outlook_sort.py → 数字-6-训练展望最终排序.txt        (按类别排序整理)
```

---

## 脚本详细说明

### 1. `1.task_id.py` — 数据爬取与分类

**功能：** 从 autoedge 平台爬取最新训练任务数据，按第4列（产品类别）或第5列分类，输出原始数据。

**输入：** 无（爬取网页数据）

**输出文件：**
| 文件 | 路径 | 说明 |
|------|------|------|
| `数字-1-标注任务明细.txt` | `Work-txt/数字-1-标注任务明细.txt` | 每行一条 task 记录，格式：`Task XXXX  状态  类别名 备注` |
| `数字-8-原始标注类别清单.txt` | `Work-txt/数字-8-原始标注类别清单.txt` | 去重后的原始类别名列表，每行一个 |
| `class.txt` | `src/class.txt` | 类别统计信息 |

**工作机制：** 从 `class.txt` 读取类别关键词，在爬取的表格数据第4列或第5列中匹配，若匹配成功则将该行写入 `数字-1-标注任务明细.txt`。同时，将命中类别的关键词写入 `数字-8-原始标注类别清单.txt`。

---

### 2. `2.model.py` — 类别标准化与 Model 数据爬取

**功能：**
1. 读取 `数字-8-原始标注类别清单.txt` 和 `数字-7-类别标准化映射规则.txt`，将原始类别名标准化浓缩
2. 对无法匹配的类别提供交互式终端处理
3. 爬取每个标准化类别的 model 训练数据

**输入文件：**
| 文件 | 说明 |
|------|------|
| `Work-txt/数字-8-原始标注类别清单.txt` | 原始类别名列表 |
| `Work-txt/数字-7-类别标准化映射规则.txt` | 映射规则：`原始类别关键词-标准化类别`，每行一条 |

**输出文件：**
| 文件 | 说明 |
|------|------|
| `Work-txt/数字-9-标准训练类别清单.txt` | 标准化后的类别列表，每行一个 |
| `Work-txt/数字-4-模型训练记录.txt` | model 训练数据，格式：`最新Task  XXXX  备注 状态  完整Task:...` |

**交互式终端特性：**
当检测到 `数字-8-原始标注类别清单.txt` 中的类别在 `数字-7-类别标准化映射规则.txt` 中无法匹配时，提供三种处理模式：
- **[1] 快速模式：** 列出所有将丢失的类别，确认后继续/返回选择
- **[2] 精细模式：** 逐类选择归类到已有 mapping 目标（按数字选择），或按 `d` 删除不再进入后续归纳
- **[q] 退出：** 不执行后续流程

**爬取逻辑：**
对每个标准化类别，在页面的筛选框中输入类别名，点击"查看详情"，提取训练数据集中前3个任务的ID（从大到小排序），连同备注信息一起写入 `数字-4-模型训练记录.txt`。

---

### 3. `3.sum_up.py` — 数据归纳汇总

**功能：** 将 `数字-1-标注任务明细.txt`（原始 task 数据）与 `数字-4-模型训练记录.txt`（model 训练任务）按类别匹配，标注每个 task 的训练状态（已训练/未训练），输出 `数字-5-训练展望原始分组.txt`。

**输入文件：**
| 文件 | 说明 |
|------|------|
| `Work-txt/数字-9-标准训练类别清单.txt` | 标准化类别列表 |
| `Work-txt/数字-7-类别标准化映射规则.txt` | 正向映射规则 |
| `Work-txt/数字-8-原始标注类别清单.txt` | 所有原始类别（辅助） |
| `Work-txt/数字-1-标注任务明细.txt` | 原始 task 数据 |
| `Work-txt/数字-4-模型训练记录.txt` | model 训练数据 |

**输出文件：** `Work-txt/数字-5-训练展望原始分组.txt`

**核心机制 — 反向映射表：**
`数字-7-类别标准化映射规则.txt` 定义了正向映射（原始→标准），例如：
```
套管油位计-表计
连续表计-表计
避雷器指针计数器-表计
```

脚本在初始化时构建**反向映射表**，将正向映射反转：
```python
{"表计": ["套管油位计", "连续表计", "避雷器指针计数器"]}
```

匹配 数字-1-标注任务明细.txt 时，不再仅用标准化关键词（如「表计」），而是用「反向映射表」将标准化关键词扩展为其对应的所有原始类别名，然后以此为搜索词去匹配 数字-1-标注任务明细.txt 的第4列或第5列。

**搜索词构建流程：**
1. 标准化关键词本身（如 `表计`）
2. `ask_keyword_mapping` 中的手动映射（如 `数显` → `数字显示`）
3. 反向映射表中该标准化类别对应的所有原始类别名（如 `套管油位计`, `连续表计` 等）

**匹配与输出：**
- **model 行匹配：** 在 `数字-4-模型训练记录.txt` 中按第6列匹配标准化关键词
- **ask 行匹配：** 在 `数字-1-标注任务明细.txt` 中按扩展后的搜索词列表匹配第4列或第5列
- 对每个匹配的 ask 行，判断其 task ID 是否在 model 的完整 Task 列表中，标注「已训练」或「未训练」

---

### 4. `4.outlook_sort.py` — 结果排序整理

**功能：** 读取 `数字-5-训练展望原始分组.txt`，按类别和训练状态分段输出 `数字-6-训练展望最终排序.txt`。

**输入：** `Work-txt/数字-5-训练展望原始分组.txt`

**输出：** `Work-txt/数字-6-训练展望最终排序.txt`

**排序逻辑：**
1. 按类别（`# 关键词 [xxx]` 标记）分组
2. 每个类别内按训练状态排序（已训练 → 未训练）
3. 每个类别块按任务数量降序排列（任务多的类别在前）

| | | 判断 5770 是否在 model 的完整Task中 | `数字-5-训练展望原始分组.txt`: `---Task 5770  已训练  套管油位计 河南漯河220kV&` |
| 4 | `4.outlook_sort.py` | 按类别和状态排序 | `数字-6-训练展望最终排序.txt`: 包含 Task 5770 |

## 数据安全保障

1. **反向映射表：** `3.sum_up.py` 自动从 `数字-7-类别标准化映射规则.txt` 构建反向索引，确保经过标准化浓缩的原始类别名仍能在 数字-1-标注任务明细.txt 中被正确匹配，不会丢失数据
2. **交互式终端：** `2.model.py` 遇到无法匹配的类别时强制用户干预，给出明确的处理选项，防止数据静默丢失
3. **异常恢复：** `2.model.py` 爬取失败时自动刷新页面继续下一个类别，失败列表在程序结束前统一输出
4. **文件完整性：** 所有输出文件写入 `Work-txt/` 目录，与源码分离，便于归档和审查
